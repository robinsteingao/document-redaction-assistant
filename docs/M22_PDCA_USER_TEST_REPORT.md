## Check: 发现问题与验证结果

### 已发现并修复的问题

1. 输出目录权限失败
   - 现象: 首轮端到端任务已跑到 `39/39`，但写出阶段失败。
   - 错误: `PermissionError: [WinError 5] 拒绝访问`
   - 根因: 桌面壳默认把输出写到安装包目录下的 `generated\desktop_output`；在真实安装或受限目录下，普通用户未必有写入权限。
   - 修复: 服务端新增输出目录解析策略，相对路径统一写入用户输出根目录；绝对路径不可写时回退到用户输出根目录；任务结果返回真实 `outputs.output_dir`。

2. 金额区间替换存在“原值再出现”风险
   - 现象: `10万元` 被替换为 `10万元以下` 时，原始敏感金额字符串仍出现在替换值中。
   - 修复: 金额区间文案改为 `低于10万 / 10万至50万 / 50万至100万` 等形式，避免复现原始金额字符串。

3. 用户无法理解大目录处理范围
   - 现象: M21 直接生成时，用户不知道哪些文件会处理、哪些会跳过。
   - 修复: 新增 `/plan-inputs` 预检接口和桌面壳“预检文件”按钮，提前列出可处理、需转换、跳过和缺失路径。

4. 批处理无进度反馈
   - 现象: M21 大样本处理超过 20 分钟无输出，用户无法判断是卡死还是处理中。
   - 修复: 新增 `/start-build` 后台任务和 `/job-status` 轮询进度，桌面壳显示当前文件、总数、阶段和最终输出。

## Act: 改进动作与下一阶段建议

M22 已满足内部小范围测试的最低条件: 一键包可构建，离线 OCR 可安装，真实样本副本可预检、后台处理、输出完整产物，且不会直接接触原始样本目录。

下一阶段不应继续只做“能跑通”，而应优先补三件事:

1. 旧版 Office/WPS 自动转换
   - 当前 `.doc/.xls/.wps` 只能被识别为需转换，不能自动处理。

3. 大批量任务体验
   - 快速 OCR 模式可用于预览和内部测试。
   - 完整 OCR 应加入任务暂停、失败重试、跳过大文件、预计耗时和处理日志导出。
